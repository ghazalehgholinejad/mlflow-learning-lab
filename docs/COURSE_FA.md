# جزوهٔ عملی MLOps و MLflow

## ۱. MLOps چه مشکلی را حل می‌کند؟

یک Notebook فقط می‌تواند نشان دهد که ایدهٔ مدل احتمالاً کار می‌کند. محصول واقعی باید بتواند بارها داده را به مدلی **قابل‌آزمایش، قابل‌ردیابی و قابل‌استقرار** تبدیل کند. MLOps مجموعه‌ای از روش‌های مهندسی برای مدیریت این چرخه است: نسخه‌بندی، بازتولیدپذیری، تست خودکار، استقرار، پایش، حاکمیت و دریافت بازخورد پس از استقرار.

MLflow تمام MLOps نیست؛ ابزاری است که چند بخش مهم آن را پوشش می‌دهد:

- **Tracking:** ثبت اجراها، پارامترها، معیارها، tagها و artifactها
- **Models:** بسته‌بندی مدل همراه وابستگی‌ها و قرارداد ورودی/خروجی
- **Registry:** نسخه‌بندی مدل و مدیریت alias، tag و توضیحات
- **Serving و integration:** کمک به انتقال مدل بسته‌بندی‌شده به مرحلهٔ inference

Git نسخهٔ کد را نگه می‌دارد؛ MLflow نتیجهٔ اجرای کد و فایل مدل را ثبت می‌کند. در پروژهٔ واقعی معمولاً هر دو لازم‌اند.

## ۲. واژه‌های اصلی

- **Experiment:** پوشهٔ منطقی برای اجراهای مرتبط
- **Run:** یک بار اجرای آموزش یا ارزیابی
- **Parameter:** مقداری که پیش از آموزش انتخاب می‌کنیم؛ مثل `max_depth`
- **Metric:** نتیجهٔ اندازه‌گیری‌شده؛ مثل F1
- **Artifact:** فایل خروجی؛ مثل نمودار یا مدل
- **Signature:** شِمای ورودی و خروجی مدل
- **Registered model:** مجموعه‌ای نام‌دار از نسخه‌های یک مدل
- **Alias:** نامی قابل‌انتقال که به یک نسخه اشاره می‌کند؛ مثل `champion`

## ۳. پروژهٔ اول: ثبت آزمایش

دستور `python projects/01_track_experiment.py` را اجرا کنید. تقسیم داده ثابت است، پارامترها ثبت می‌شوند، چهار metric و confusion matrix ذخیره می‌شود و مدل همراه signature بسته‌بندی می‌گردد. مقدار `C` را تغییر دهید و دوباره اجرا کنید. در رابط MLflow دو run را مقایسه کنید و توضیح دهید آیا اختلاف مشاهده‌شده از نظر عملی مهم است یا نه.

پارامتر می‌گوید چه چیزی را انتخاب کردیم؛ metric می‌گوید چه نتیجه‌ای گرفتیم. Tag برای زمینهٔ قابل‌جست‌وجو است و artifact فایل‌های بزرگ‌تر را نگه می‌دارد.

## ۴. پروژهٔ دوم: مقایسهٔ مدل‌ها

دستور `python projects/02_compare_models.py` را اجرا کنید. دو مدل دقیقاً با یک تقسیم داده آموزش می‌بینند. کد بر اساس F1 و سپس accuracy مرتب می‌کند، leaderboard می‌سازد و run منتخب را tag می‌زند.

این سیاست شفاف است، اما برای production کافی نیست. در سیستم واقعی latency، calibration، عملکرد گروه‌های مختلف، هزینه و عدم‌قطعیت نیز مهم‌اند. برای انتخاب مدل مرتباً از test set استفاده نکنید؛ انتخاب باید با validation یا cross-validation انجام شود و test set برای برآورد نهایی باقی بماند.

## ۵. پروژهٔ سوم: Model Registry

ابتدا `python projects/03_registry_aliases.py` را اجرا کنید. یک نسخه در Registry ثبت، alias به نام `candidate` ایجاد و وضعیت اعتبارسنجی `pending` می‌شود. اجرای همان دستور با `--promote`، alias به نام `champion` را نیز به نسخهٔ جدید منتقل می‌کند و وضعیت را `approved` می‌گذارد.

مزیت alias این است که کد inference می‌تواند همیشه آدرس `models:/cancer-risk-classifier@champion` را بخواند و تیم بدون تغییر آن کد، نسخهٔ مقصد را عوض کند. در این آزمایش تصمیم promotion صریح است، ولی سامانهٔ تأیید production کامل پیاده‌سازی نشده است.

## ۶. معماری محلی و تیمی

این پروژه از SQLite و artifact محلی استفاده می‌کند و برای یادگیری یک نفر مناسب است. تیم معمولاً Tracking Server مشترک، پایگاه‌دادهٔ مدیریت‌شده، object storage و کنترل دسترسی و شبکه دارد.

## ۷. اشتباه‌های رایج

- ثبت امتیاز بدون ثبت نسخه یا منشأ داده
- ذخیرهٔ مدل بدون signature و input example
- مقایسهٔ اجراهایی که تقسیم دادهٔ متفاوت دارند
- تصور اینکه بهترین validation score کیفیت production را ثابت می‌کند
- commit کردن `mlflow.db`، پوشهٔ `mlruns` یا فایل‌های مدل در Git
- جابه‌جایی alias اصلی بدون معیار اعتبارسنجی و برنامهٔ rollback

## ۸. تمرین‌ها

1. معیار ROC AUC را اضافه و تفاوت کاربردش با accuracy را توضیح دهید.
2. مدل سومی اضافه کنید و بازتولیدپذیری مقایسه را حفظ کنید.
3. latency را وارد leaderboard و سیاست چندمعیاره تعریف کنید.
4. مدل `models:/cancer-risk-classifier@champion` را بارگذاری و پیش‌بینی کنید.
5. تستی بنویسید که promotion مدل با F1 پایین را رد کند.
6. در یک branch جدا، artifact محلی را با object storage جایگزین کنید.

## ۹. چه زمانی این مبحث را یاد گرفته‌اید؟

وقتی بتوانید دلیل هر فیلد ثبت‌شده را توضیح دهید، یک run را بازتولید کنید، سیاست انتخاب مدل را توجیه کنید، مدل را با alias بخوانید و کمبودهای مسیر production را نام ببرید، پایهٔ این مبحث را یاد گرفته‌اید.
